Game Companion / GamePath Presentation

GamePath 本地攻略知識庫

用地端 Qwen 做意圖分流，用 SQLite FTS5 + RAG Lite 快速查本地攻略， 本地不足或需要複雜推理時，再交給雲端 Hermes Agent（GPT5.5）/ Tavily， 最後用低劇透 Hint 形式回覆玩家。

Cloud + Local Hybrid SQLite FTS5 RAG Lite Qwen Intent Gate Hermes Agent GPT5.5 Tavily Web Search LLM-wiki Ready
核心目的： 玩家卡關時不用離開遊戲去翻長篇攻略；常見問題走本地 GamePath 快速回答， 本地不知道或需要最新版資訊時才上雲，降低延遲、成本與暴雷風險。

1. GamePath 架構圖與流程

Step 1

玩家輸入

文字、語音、截圖或 HUD 需求進入遊戲陪伴 Overlay。

Step 2

Qwen Intent Gate

判斷是攻略、一般聊天、UI 指令、玩家記憶、HUD，或 web/current 問題。

Step 3

GamePath RAG Lite

攻略問題才查 SQLite FTS5、chunk index 與 metadata。

Step 4

Evaluator

用 coverage、core overlap、area、tags、trust state 判斷命中品質。

Step 5

Hermes GPT5.5 / Tavily

本地不足、最新版、patch 或網路攻略需求才進雲端 Agent 搜尋與整理。

Step 6

Hint 回覆

整理成 Hint 1/2/3，避免一開始就暴雷。

SQLite 查詢入口，保存 entry、chunk、FTS5、metadata。
Markdown Notes 人可讀攻略本體，未來可直接成為 LLM-wiki 頁面來源。
Local Qwen / Cloud Hermes Qwen 在地端 iGPU 做分流；Hermes Agent（GPT5.5）負責雲端推理、濃縮與外部工具。

2. RAG Lite 解釋

目前做法

  • 寫入：攻略濃縮後保存成 Markdown，並建立 SQLite entry / chunk。
  • 索引：用 SQLite FTS5 + 中文 n-gram / search terms 擴展查詢。
  • 召回：用玩家原始問句查 entry 與 chunk，不讓 Qwen 改寫取代主查詢。
  • 排序：依 match coverage、core overlap、metadata、area/entity/tags rerank。
  • 決策：direct、summarize、miss；miss 才進 Hermes/Tavily。
方案 檢索方式 資源需求 適合度
GamePath RAG Lite SQLite FTS5 + chunk + metadata rerank 低，不需 embedding model 目前採用
Vector RAG Embedding + vector similarity 中到高，需要額外模型與索引 未來資料量變大可選配
GraphRAG 實體、關係、事件圖譜 高，需要圖資料與摘要維護 未來 LLM-wiki / 世界觀整理可考慮

direct / summarize / miss

direct 本地資料高信心命中；用地端 Qwen 整理成 Hint，不需要查網路。
summarize 有相關段落，但需要模型濃縮、重組或換成玩家可用提示。
miss 本地不足或候選太像硬湊；才交給 Hermes GPT5.5 / Tavily。

4. 優劣分析

優勢

  • 本地快取：已保存攻略可直接命中，不必每次查網路。
  • 低資源：SQLite FTS5 不需要額外 embedding model，適合 iGPU。
  • 可打包：SQLite + Markdown 易於 offline installer 與團隊開發使用。
  • 可控：Qwen 只做意圖 gate，不直接操作 UI 或系統。
  • 雲地分工：地端負責快取與分流，雲端 Hermes GPT5.5 負責複雜推理與查網路。
  • 低劇透：回答用 Hint 1/2/3，而不是直接吐完整攻略。

限制

  • Qwen gate 慢：iGPU 平均約 13.3s，玩家體感會受影響。
  • 非完整語意：RAG Lite 沒有 embedding，同義詞很遠時會比較吃力。
  • 不可無腦查：純 SQLite 會把非攻略問題硬湊成攻略。
  • 資料治理需求：資料變大後要管理版本、可信度、重複與過期內容。
  • Qwen 改寫風險：改寫 query/tags 會讓 Top-1 從 100% 降到 80%。
  • 雲端依賴：Hermes GPT5.5 / Tavily 需要網路、API 設定與延遲預算。

目前取捨

這版不是追求最強 RAG，而是先追求「可打包、可離線、有足夠準確度」。 對遊戲陪伴來說，玩家正在玩遊戲，穩定與低打擾比一次回答塞滿所有知識更重要。

何時需要升級

當資料量成長到跨遊戲、跨任務線、同義詞非常多，或玩家常用截圖加模糊描述時， 才需要加入 embedding reranker、向量索引，甚至 GraphRAG 的實體關係整理。

5. 未來與 LLM-wiki 的整合

短期

  • 保留 Qwen gate + 原始問句檢索。
  • 加 route cache，降低 13.3s 的重複判斷成本。
  • 持續保存 Hermes/Tavily 濃縮後的可重用提示。

中期

  • Markdown notes 轉成 LLM-wiki 頁面。
  • 依 game_id、area、entity_type 建立目錄。
  • 加入 verified / disputed / deprecated 狀態。

長期

  • 資料量超過大型 wiki 後再引入 embedding reranker。
  • 需要跨角色、地點、事件推理時再評估 GraphRAG。
  • 讓 GamePath 成為雲端/地端模型共用的穩定知識層。
整合方向： Markdown 是知識本體，SQLite 是可重建索引，地端 Qwen 與雲端 Hermes GPT5.5 是使用知識的推理層。 這樣即使後端 Agent 快速迭代，攻略知識也不會被任意取代。

GamePath 現在

偏向「可查的攻略提示庫」：每筆資料已濃縮、可被 SQLite 搜尋，也能顯示在 GamePath 視窗。

LLM-wiki 未來

偏向「可閱讀、可維護的知識頁」：同一遊戲下按區域、道具、敵人、任務線整理成頁面。

兩者關係

不是替代關係；Markdown notes 可升級成 wiki 來源，SQLite 索引可從 wiki 內容重新產生。

6. 結論

目前最穩流程

地端 Qwen 判斷要不要查，GamePath 用玩家原句查，雲端 Hermes Agent（GPT5.5）負責整理與補網路。

GamePath RAG Lite 已經能支撐數千筆本地攻略快速查找； Qwen gate 能把非攻略問題擋掉，避免 SQLite 硬湊錯誤攻略。

玩家端呈現

回答不直接暴雷，而是逐步提示；泡泡狀態會顯示路徑、命中信心與主要耗時，讓玩家知道是本地命中還是上雲查找。

Hint 1
給方向與觀察點。
Hint 2
給路線或互動物件。
Hint 3
接近答案，但仍避免過度劇透。
一句話總結： GamePath 是把「玩家已查過、可重用、低劇透」的攻略沉澱在本地； Qwen 決定該不該用它，Hermes GPT5.5 在本地不足時補齊外部知識。
